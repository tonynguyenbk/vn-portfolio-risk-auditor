# Data dictionary

Definitions for every dataset the project reads, and the provenance record for
the real market data bundled with it.

---

## 1. Market data — `market_data.csv`

Long form: one row per ticker per trading day.

| Column | Type | Required | Description |
|---|---|---|---|
| `date` | ISO `YYYY-MM-DD` | Yes | Trading day. Must parse; unparseable rows are dropped and counted. |
| `ticker` | Uppercase string | Yes | Instrument identifier. Trimmed and upper-cased on load. |
| `close` | Positive number | Yes | Closing price. Non-numeric or non-positive rows are dropped — a zero or negative price cannot yield a log return. |
| `adjusted_close` | Positive number | No | Preferred over `close` when present; the engine reports which basis it used. |
| `volume` | Integer | No | Not used in any calculation. Present for completeness. |
| `sector` | String | No | Used for sector concentration. Defaults to `Unclassified`. |

**Constraints**

- `(date, ticker)` must be unique. Duplicates are removed keeping the first
  occurrence, counted, and reported as a data-quality warning.
- Assets are aligned on the **intersection** of their trading dates. Any date on
  which a selected asset did not trade is dropped for all of them.
- Missing observations are **never forward-filled**.

**Example**

```csv
date,ticker,close,volume,sector
2015-01-05,FPT,6489.7,273550,Technology
2015-01-05,VCB,9298.12,310010,Banking
2015-01-05,VNINDEX,544.45,91834620,Benchmark
```

## 2. Portfolio — `portfolio.csv`

| Column | Type | Required | Description |
|---|---|---|---|
| `ticker` | Uppercase string | Yes | Must exist in the market dataset. |
| `weight` | Number in [0, 1] | Yes | Portfolio weight. |
| `sector` | String | No | Falls back to `Unclassified`. |

**Validation rules** (each produces a specific error code)

| Rule | Code |
|---|---|
| Weights sum to 1 within 1e-6 | `WEIGHT_SUM` |
| No negative weights — this version is long-only | `NEGATIVE_WEIGHT` |
| At least 2 assets | `TOO_FEW_ASSETS` |
| At most 10 assets | `TOO_MANY_ASSETS` |
| Every ticker present in the market data | `TICKER_NOT_IN_MARKET_DATA` |
| Weights numeric | `WEIGHT_NOT_NUMERIC` |

**Example**

```csv
ticker,weight,sector
FPT,0.25,Technology
VCB,0.25,Banking
HPG,0.2,Materials
MWG,0.15,Retail
VNM,0.15,Consumer
```

## 3. History requirements

| Condition | Effect |
|---|---|
| Aligned observations < `rolling_window + 1` | Analysis **blocked** (`INSUFFICIENT_HISTORY`) |
| Aligned observations < `rolling_window + 100` | Warning (`THIN_HISTORY`); analysis proceeds |
| More than 2% of candidate dates lost to alignment | Warning (`EXCESSIVE_ALIGNMENT_LOSS`) |

## 4. The bundled demonstration dataset

**Real historical data.** Daily closes for five HOSE-listed stocks and the
VN-Index, adjusted for dividends and splits by the provider.

| Property | Value |
|---|---|
| Retrieval script | `backend/scripts/fetch_market_data.py` |
| Period requested | 2015-01-01 → 2026-10-29 |
| First / last observation | 2015-01-05 → 2026-10-29 |
| Trading days | 2,951 (identical calendar for all six series) |
| Rows | 17,706 |
| Instruments | FPT, VCB, HPG, MWG, VNM, plus VNINDEX as benchmark |
| Price unit | VND per share (stocks); index points (VNINDEX) |

| Ticker | Company | Sector | Weight |
|---|---|---|---:|
| FPT | FPT Corporation | Technology | 0.25 |
| VCB | Vietcombank | Banking | 0.25 |
| HPG | Hoa Phat Group | Materials | 0.20 |
| MWG | Mobile World Investment | Retail | 0.15 |
| VNM | Vinamilk | Consumer | 0.15 |

The weights are a fixed, hypothetical allocation chosen for the demonstration.
They are not a recommendation and do not describe any real holding.

**Back-adjusted prices.** Because adjustment is applied backwards from the
latest date, early prices sit well below what was quoted on the exchange at the
time (FPT's adjusted 2015 close is about 6,490 VND). Returns are what matter
to every calculation, and those are correct only on an adjusted series.

**Reproducibility.** Real data cannot be regenerated byte-identically from a
seed: the provider can revise history or re-base its adjustments at any time.
The committed CSVs are therefore the dataset of record. `manifest.json` records
the source, the frozen request window, the retrieval date and a SHA-256 of each
file, and CI checks the files against those checksums with
`backend/scripts/verify_demo_data.py`. Two fetches on the retrieval date
produced byte-identical files. Line endings are forced to LF via
`.gitattributes`, without which a Windows checkout would alter the files and
break that check for a reason unrelated to the data.

**The synthetic generator.** `backend/scripts/generate_demo_data.py` (seed 42,
fictional tickers `ASSET_A` … `ASSET_E`) is kept as a test fixture whose
properties are known by construction. It no longer writes the shipped files and
requires an explicit `--output` directory.

## 5. Precomputed analysis

Produced by `backend/scripts/precompute_demo_analysis.py` and imported by the
dashboard at build time.

| File | Contents |
|---|---|
| `analysis.json` | Full `AnalysisResult` — metrics, curves, correlation, contributions, limits, assumptions |
| `backtest.json` | Walk-forward series for the primary pair, plus a summary row per model × confidence |
| `stress.json` | Three historical scenarios located in the dataset and replayed against the weights |

These must be regenerated whenever the engine or the dataset changes.

## 6. Provenance record for the bundled real data

Recorded as PRD 8.6 requires before any result derived from real data is
reported.

| Field | Value |
|---|---|
| Source | Vietcap (Vietcap Securities), chart data service |
| Endpoint | `POST https://trading.vietcap.com.vn/api/chart/OHLCChart/gap-chart`, body `{"timeFrame":"ONE_DAY","symbols":[<ticker>],"to":1793318400,"countBack":5000}` (`to` = 2026-10-30 00:00 UTC, frozen) |
| Retrieval date | 2026-10-30 |
| Licence / terms of use | Undocumented public endpoint; used for non-commercial educational research; terms not formally published. |
| Terms reviewed on | 2026-10-30 — no published terms found for this endpoint |
| Redistribution permitted? | Not stated by the provider. Bundled here solely so a personal, non-commercial study project is reproducible; attribution to Vietcap is preserved in the UI and in `manifest.json`. |
| Ticker coverage | FPT, VCB, HPG, MWG, VNM (HOSE) and VNINDEX |
| Period covered | 2015-01-05 → 2026-10-29 (requested 2015-01-01 → 2026-10-29; 1 and 2 January 2015 were market holidays) |
| Price basis (`close` / `adjusted_close`) | `close` column holding **adjusted** closes, as supplied |
| Corporate-action adjustment method | Adjusted close as provided by Vietcap (dividends and splits, back-adjusted). The provider does not document its method; it is used unchanged and not re-derived. |
| Missing-data handling | None needed: all six series share the same 2,951 trading days, so intersection alignment drops nothing. Nothing is forward-filled or interpolated. |
| Rows removed during cleaning, and why | Only bars outside the requested period are dropped. No in-period row was removed. Prices are written with at most 2 decimals; the source supplies no finer precision, so this was verified to change no value. |
| Final analysis period after alignment | 2015-01-05 → 2026-10-29, 2,951 observations, 2,950 daily returns, 2,700 walk-forward test days |
| Known gaps or anomalies | Longest gap between trading days: 11 calendar days (Tet, February 2015). Largest daily moves are ±7.26% in log terms (= a −7% limit-down day), e.g. FPT and VCB on 2025-04-08, VNM on 2020-03-23; none exceeds the HOSE ±7% limit. |

**Sanity checks run at retrieval** (`fetch_market_data.py`, which writes nothing
and exits non-zero if any fails):

- non-positive or non-finite prices, duplicate dates, weekend dates;
- any daily |log return| above 7.5% — beyond the HOSE ±7% daily limit, so a
  sign of a bad print or a missed corporate-action adjustment;
- any gap of more than 15 calendar days between consecutive trading days;
- a series starting or ending more than 15 days inside the requested period.

All six series passed every check.

**Retrieval rules followed**

- Standard-library HTTP only; no third-party scraping package. Requests are
  spaced about one second apart.
- The dataset is frozen and checksummed, so results stay reproducible when the
  upstream source changes.
- The application does not depend on the endpoint at run time: the dashboard
  reads the committed files, and the endpoint is contacted only when the
  retrieval script is run by hand.

---

## 7. Privacy

Uploaded files are parsed in memory and discarded. Nothing is written to disk,
nothing is retained after the response is built, and no personal data, account
identifier or credential is collected at any point.
